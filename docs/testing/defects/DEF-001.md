# Defect Report — DEF-001

**Defect ID**: DEF-001  
**Title**: Notification permission denial prevents audio track list from loading even when audio storage permission is granted  
**Date Logged**: 2026-09-19  
**Reported By**: User / QA Tester  
**Environment**: Android 13+ (API 33+) Device / Emulator  
**Build / Version**: v1.0.0 (versionCode 1)  
**Module**: Permissions / MainActivity  
**Severity**: Major  
**Priority**: P1 - High  

---

## 1. Description & Preconditions

* **Preconditions**: MyTune application installed freshly on Android 13+ device with permissions revoked.
* **Summary**: On Android 13+ startup, the app requests both `POST_NOTIFICATIONS` and `READ_MEDIA_AUDIO`. If a user denies `POST_NOTIFICATIONS` but grants `READ_MEDIA_AUDIO`, the app treats the overall permission check as failed (`allGranted = false`), shows the Toast `"Permission required to access audio files"`, and fails to load audio tracks into the UI list.

---

## 2. Steps to Reproduce

1. Launch MyTune on Android 13+ with clean permission state.
2. When prompted for Notification permission (`POST_NOTIFICATIONS`), select **Don't Allow / Deny**.
3. When prompted for Audio media permission (`READ_MEDIA_AUDIO`), select **Allow**.
4. Observe the main screen.

---

## 3. Expected vs Actual Results

* **Expected Result**: Audio tracks load successfully into the "All Songs" list view since `READ_MEDIA_AUDIO` permission was granted. Only status bar media notifications should be disabled.
* **Actual Result**: App displays Toast `"Permission required to access audio files"` and leaves the track list completely empty.

---

## 4. Evidence & Reproducibility

* **Reproducibility**: Always (100%)
* **Evidence**: Source inspection of `permissionLauncher` in `MainActivity.java`:
  ```java
  for (Boolean isGranted : result.values()) {
      if (!isGranted) {
          allGranted = false;
          break;
      }
  }
  ```

---

## 5. Lifecycle & Resolution Tracking

* **Status**: Closed / Resolved  
* **Root Cause Analysis**: `MainActivity.java` used `registerForActivityResult(RequestMultiplePermissions())` requiring ALL requested permissions in `result.values()` to be `true`. Notification permission (`POST_NOTIFICATIONS`) is an optional feature permission and should not block local storage track loading.  
* **Resolution**: Updated `permissionLauncher` in `MainActivity.java` to specifically check `READ_MEDIA_AUDIO` (on API 33+) or `READ_EXTERNAL_STORAGE` (on API < 33). If audio media permission is granted, `loadSongs()` is executed regardless of whether `POST_NOTIFICATIONS` was allowed or denied.
